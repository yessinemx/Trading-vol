# FX Option Backtester — User Guide

A modular backtesting framework for FX options on **EUR/NOK**, built around the
**Garman–Kohlhagen** model with daily delta hedging and full Greeks P&L attribution.

---

## 1. Methodology

### 1.1 Pricing — Garman–Kohlhagen

FX options are priced in the **domestic (quote) currency**. For EUR/NOK the quote
currency is **NOK**, so all premia, P&L and Greeks are expressed in NOK.

$$
C = S_0\,e^{-r_f T} N(d_1) - K\,e^{-r_d T} N(d_2), \qquad
P = K\,e^{-r_d T} N(-d_2) - S_0\,e^{-r_f T} N(-d_1)
$$

$$
d_1 = \frac{\ln(S_0/K) + (r_d - r_f + \tfrac12\sigma^2)T}{\sigma\sqrt{T}},
\qquad d_2 = d_1 - \sigma\sqrt{T}
$$

where $r_d$ is the domestic (NOK) rate, $r_f$ the foreign (EUR) rate. The pricer
returns price and the first-order Greeks **Δ, Γ, ν, Θ, ρ_d, ρ_f**, with vega scaled
per 1% vol move and theta per calendar day.

### 1.2 Market data & units

| Dataset        | File                          | Units handling                                                        |
| -------------- | ----------------------------- | --------------------------------------------------------------------- |
| Spot           | `*spot*.parquet`              | NOK per EUR, used as-is                                               |
| Forward points | `*forwardcurve*.parquet`      | pips → divided by 10,000; **outright = spot + points**                |
| Deposit curves | `*depocurve*.parquet`         | % → decimal; NOK tagged **domestic**, EUR **foreign** (by RIC prefix) |
| Vol surface    | `*volatilitysurface*.parquet` | % → decimal                                                           |

Stacked frames are **pivoted once** into `{date: sub-frame}` maps so the day-by-day
loop avoids repeated boolean masks.

### 1.3 Interpolation / extrapolation

| Object                | Interpolation    | Extrapolation                                             |
| --------------------- | ---------------- | --------------------------------------------------------- |
| Vol surface (strike)  | **cubic spline** | **linear** (boundary-slope extension, floored > 0)        |
| Vol surface (time)    | linear           | linear                                                    |
| Forward & rate curves | linear           | linear (duplicate tenors collapsed to keep slopes finite) |

### 1.4 Strategy life-cycle

1. **Roll scheduler** generates rebalancing dates (`W-FRI`, `MS`, `QS`, …).
2. On each roll date, every **leg** is opened: its strike is resolved from the
   target delta (ATM → forward outright; otherwise delta is inverted on a strike grid).
3. The **sizing designer** (`Strategy.size`) converts the target notional into a
   per-leg traded notional (default scales by the leg ratio).
4. Positions are **settled at intrinsic value** on expiry.

### 1.5 Daily delta hedging

Every business day the engine computes the **net option delta** (in foreign-ccy
units) and holds the opposite amount as a spot position. The hedge is rolled at the
prevailing spot; its realised P&L is booked daily. Total P&L is therefore:

$$\text{PnL}_{\text{day}} = \underbrace{\Delta\text{MTM}_{\text{options}}}_{\text{option leg}} + \underbrace{\text{hedge PnL}}_{\text{spot leg}}$$

### 1.6 Performance analyticsS

Option-aware metrics on daily P&L: **Sharpe**, **Sortino** (downside-only),
**max drawdown**, historical **VaR 95%** and **CVaR/Expected Shortfall 95%**,
win rate, and annualised volatility.

### 1.7 Greeks P&L attribution

The daily option P&L of legs alive on two consecutive days is decomposed via a
second-order Taylor expansion:

$$dP \approx \Delta\,dS + \tfrac12\Gamma\,dS^2 + \nu\,d\sigma + \Theta\,dt + \varepsilon$$

Computing it **position-by-position over continuing legs** keeps premium cash-flows
on rolls out of the decomposition, leaving only a small cross-Greek residual
(vanna/volga + discretisation). The reported delta leg is **net of the hedge**.

### 1.8 Signals

A signal maps the spot history up to a roll date onto a boolean (trade / skip).
Built-ins: `momentum_signal` (price vs SMA) and `realised_vol_signal`. Attach one to
a strategy via `signal_fn`.

## 2. Architecture

```
src/
├── data/loader.py         → ingest + unit-normalise + pivot stacked Parquet
├── curves/interpolator.py → linear curve interp/extrap (rates, forward)
├── volatility/surface.py  → cubic-spline (strike) / linear (time) vol surface
├── pricing/…              → Garman-Kohlhagen price + Greeks
├── strategies/…           → Straddle, CallRatioSpread, CalendarSpread, signals, sizing
├── portfolio/position.py  → option positions, cash, spot delta-hedge book
├── analytics/…            → performance metrics + Greeks attribution
└── engine.py              → orchestrates: roll → price → hedge → MTM → attribute
notebooks/backtester.ipynb → end-to-end walkthrough
outputs/                   → charts, CSV results (generated by the notebook)
```

This mirrors the project architecture diagram: per-strategy **roll scheduler**,
**sizing designer** and **contract specification** feed a shared **Garman–Kohlhagen
pricing engine**, whose output is consumed by a **time aggregator** producing
standard-date MTM updates and roll-date open/close events plus cash management.

## 3. How to use

### 3.1 Install

```bash
poetry install        # or: pip install pandas numpy scipy matplotlib seaborn pyarrow jupyter
```

Place the four Parquet files in `data/`.

### 3.2 Run a backtest

```python
from src.engine import Backtester
from src.strategies.straddle import Straddle

bt = Backtester("data")
bt.load_data()

strategy = Straddle(tenor_days=30, direction=1)
results = bt.run(strategy, start="2021-01-01", end="2024-12-31",
                 notional=1_000_000, roll_freq="W-FRI")

print(results["metrics"])
results["daily_pnl"].cumsum().plot()
```

`results` keys: `metrics`, `daily_pnl`, `components` (option vs hedge),
`greeks`, `attribution`, `portfolio`.

### 3.3 Add a signal

```python
from src.strategies.signals import momentum_signal
strategy = Straddle(tenor_days=30, signal_fn=lambda h: momentum_signal(h, 20))
```

### 3.4 Notebook & tests

- End-to-end walkthrough: [`notebooks/explore.ipynb`](../notebooks/explore.ipynb)
- Unit tests: `poetry run pytest` (pricing parity, interpolation, analytics).

## 4. Quantitative deep dive — delta-hedged long straddle

**Setup.** Long 30-day ATM straddle on EUR/NOK, rolled weekly, delta-hedged daily,
2021-01 to 2024-12, 1,000,000 notional.

**Economic rationale.** Once delta is neutralised, the straddle is a pure bet on
**realised vs implied volatility**. Its carry is approximately

$$\text{PnL} \approx \tfrac12\,\Gamma\,S^2\big(\sigma_{\text{realised}}^2 - \sigma_{\text{implied}}^2\big)\,dt$$

i.e. it harvests gamma when the market moves more than the implied vol paid, and
bleeds theta when it does not.

**Results (this backtest).**

| Metric          | Always-on | Momentum-gated |
| --------------- | --------- | -------------- |
| Total P&L (NOK) | ≈ 1.30 M  | ≈ 1.68 M       |
| Sharpe          | 0.13      | 0.23           |
| Sortino         | 0.15      | 0.24           |
| Max drawdown    | ≈ −2.87 M | ≈ −1.61 M      |

The **Greeks attribution** confirms the economics: cumulative **gamma ≈ +21 M** is
almost entirely offset by **theta ≈ −24 M**, with hedged-delta, vega and residual all
small — the textbook signature of a hedged long-gamma book.

**Read-through to EUR/NOK.** NOK is an oil-sensitive, lower-liquidity currency whose
volatility clusters in risk-off episodes (e.g. 2022). The straddle's gamma harvest
dominates during those bursts and decays in calm, range-bound regimes. A simple
**momentum filter** removes some low-vol roll periods, roughly **doubling the Sharpe
and halving the drawdown** while keeping gross P&L — a favourable risk-adjusted trade-off.

**Limitations.** Mid-price execution (no bid/ask spread or hedging cost), discrete
daily hedging (gamma slippage between rebalances), and a Taylor attribution that omits
higher-order cross-Greeks (vanna/volga), visible as the residual term.
